# موتور گالری (gallery-dl)

LeechX دو موتور دانلود دارد:

| موتور | برای چه چیزی | نمونه |
|---|---|---|
| **yt-dlp** | ویدیو، صدا، پخش زنده، ۱۷۰۰+ سایت | YouTube، TikTok، Twitter (ویدیو) |
| **gallery-dl** | عکس، آلبوم، پروفایل، ۳۸۰+ سایت | اینستاگرام، پینترست، Pixiv، Kemono، Reddit، سایت‌های گالری بزرگسال |

## چطور کار می‌کند؟

1. کاربر لینک می‌فرستد.
2. ربات اول با yt-dlp بررسی می‌کند.
3. اگر yt-dlp گفت «unsupported» و gallery-dl آن دامنه را بشناسد، لینک
   خودکار به موتور گالری می‌رود (بدون منوی کیفیت، مستقیم به صفحهٔ تحویل).
4. دانلود در یک subprocess انجام می‌شود تا دکمهٔ لغو و مهلت زمانی واقعاً
   کار کند.
5. تحویل:
   - حالت **ویدیو/مدیا** → عکس‌ها در آلبوم‌های ۱۰تایی تلگرام.
   - حالت **فایل** → همهٔ فایل‌ها خام و جدا.
   - مقصد **لینک مستقیم** → آلبوم به یک فایل ZIP تبدیل و لینک می‌شود.

## محدودیت‌ها و تنظیمات

- تعداد فایل هر لینک گالری با متغیر محیطی `GALLERY_MAX_ITEMS` کنترل می‌شود
  (پیش‌فرض ۵۰، حداکثر ۲۰۰). یک پروفایل اینستاگرام هزاران عکس دارد؛ بدون
  این سقف سرور پر می‌شود.
- کوکی‌های Netscape آپلودشده در پنل ادمین خودکار به gallery-dl هم داده
  می‌شوند (پست‌های خصوصی/لاگین‌دار).
- پروکسی تنظیم‌شده (`PROXY`) به gallery-dl هم پاس داده می‌شود.
- اگر `gallery-dl` نصب نباشد، ربات مثل قبل کار می‌کند و فقط قابلیت گالری
  غیرفعال است.

## نصب / بروزرسانی

```bash
pip install -U "gallery-dl>=1.29,<2"
# یا نسخهٔ توسعه:
pip install -U --force-reinstall "git+https://github.com/mikf/gallery-dl.git@master"
```

دیپلوی ZIP از داخل ربات هم چون `requirements.txt` عوض شده باشد، وابستگی را
قبل از اعمال سورس نصب می‌کند.

## عیب‌یابی

| نشانه | علت رایج | راه‌حل |
|---|---|---|
| «Unsupported URL» | دامنه در هیچ‌کدام از دو موتور نیست | نسخهٔ gallery-dl/yt-dlp را آپدیت کن |
| «Login or cookies required» | پست خصوصی است | کوکی همان سایت را در پنل ادمین آپلود کن |
| «403 / 404» | پست حذف یا محدود شده | لینک را در مرورگر تست کن |
| فقط چند فایل آمد | سقف `GALLERY_MAX_ITEMS` | مقدار را بالا ببر (حداکثر ۲۰۰) |
